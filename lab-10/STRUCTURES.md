# ЛР-10. Структури папок

Ці таблиці заповнюєте ви: рядок «Де живе кошик» після кожної структури
(§4.3–§4.6) і «Вибір структури» наприкінці (§4.7). Рядок «Пакет» — лише якщо
виконуєте додаткове завдання §4.9. Як рахувати теки, описано в інструкції,
§4.2.

## Де живе кошик

У яких теках лежать шість файлів кошика: сховище, `useCart`,
`AddToCartButton`, `CartLine`, сторінка кошика й шапка з лічильником.
«Тек» — скільки їх, «Теки» — їхні шляхи через кому.

| Структура                  | Тек | Теки |
| -------------------------- | --- | ---- |
| За типом файлів (§4.3)     |  4  |`src/components/`, `src/hooks/`, `src/pages/`, `src/store/`|
| За маршрутами (§4.4)       |  3  | `src/app/`, `src/routes/cart/`, `src/shared/` |
| За функціональністю (§4.5) |     |      |
| FSD (§4.6)                 |  4  | `src/app/`, `src/entities/cart/model/`, `src/features/add-to-cart/ui/`, `src/pages/cart/ui/` |
| Пакет (§4.9)               |     |      |

## Вибір структури

Описи проєктів, з чого обирати і як пояснити вибір — в інструкції, §4.7.
«Чому»: що в проєкті важливо і чому обрана структура для цього підходить.

| Проєкт                             | Структура | Чому |
| ---------------------------------- | --------- | ---- |
| 1. Прототип на хакатоні            | За маршрутами | За 24 години трьом людям треба швидко розділити роботу над п'ятьма екранами, не витрачаючи час на складну архітектуру; маршрут дає зрозумілу межу. Якщо ідея переможе, спільні бізнес-частини можна буде винести окремо. |
| 2. Блог і документація на Next.js  | За маршрутами | У 40 сторінок власна розмітка, спільні лише шапка й підвал. Структура за маршрутами відповідає file-based routing Next.js і тримає зміни сторінок локальними. |
| 3. Адмінка для бариста             | За функціональністю | 15 екранів згруповані навколо замовлень, складу й змін, а їхні таблиці та форми різні. Групування за бізнес-функціями допоможе команді розвивати кожну ділянку окремо, залишивши спільними лише кнопки й таблицю. |
| 4. Інтернет-магазин кави           | Feature-Sliced Design | Три команди роками розвиватимуть сторінки, де повторюються кошик і картка товару. Шари та слайси з публічними API розділять сутності, дії й інтерфейс та зменшать конфлікти між командами. |
| 5. Три застосунки мережі кав'ярень | Пакети + за маршрутами | Спільні дизайн-система й кошик варто оформити пакетами, щоб три застосунки не дублювали код і могли використовувати його узгоджено. Усередині кожного застосунку групування за маршрутами збереже його власні екрани окремими. |
